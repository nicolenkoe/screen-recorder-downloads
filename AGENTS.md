# Screen Recorder project instructions

The user has authorized publishing updated builds without a separate request or confirmation.

After implementing agreed application changes, complete relevant checks, assign a new version, build and publish the changed platform's distributable to GitHub Releases, verify the actual published file and the website's latest-download selection, then report the new version and direct download link. Do not leave implemented application changes unpublished merely because the user stopped sending messages. Report any build/publish blocker honestly.

Use versioned EXE/APK filenames. Keep published releases immutable; increment the version for a changed binary. Sign Android updates with the existing private key; never commit signing material or print secrets. Clearly label experimental builds and distinguish automated checks from device runtime validation. Do not publish a known-broken build or describe an old file as new.

This instruction concerns work during an active task, not scheduling work after the assistant turn ends. Apply it to future tasks in this repository.
